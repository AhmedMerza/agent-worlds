# Changelog

Newest first. Dates are commit dates.

## 2026-10-22
- Qwen Code permission requests are answered in Qwen's own terminal prompt; Needs you shows the request with no Allow/Deny, as for Codex and Kimi (#17). Qwen waits about 4 seconds on its PermissionRequest hook before drawing its prompt, then drops the hook: the card vanished, the terminal sat on a spinner meanwhile, and Allow/Deny only worked in that window. The hook now answers at once, so Qwen's prompt shows straight away and the card stays until the request is answered. Denying or dismissing it with Esc, after which Qwen sends only an `idle_prompt` notification, now clears the card too (it used to stay, and covered the next request). Qwen's memory pass after a finished turn (tool calls with no agent id and no Stop after them) no longer moves a done session back to working for good. Checked on Qwen Code 0.25.3 and 0.26.0.

## 2026-10-20
- After a server restart, sessions of every agent are picked up again, not just Claude's (#58). Before, a Codex, Qwen, Kimi, Gemini or agy session stayed invisible until its next hook — an idle one forever. The process scan now matches their binaries too (Kimi's renamed process, the Node-script CLIs behind `node`) and names each running session from the agent's own files: Kimi's session folder (or its `--session` flag), Qwen's per-pid session file, Codex's rollout log, Gemini's chat, agy's history. State and your last prompt come back where those files record them (Qwen's record neither, so it comes back idle). Plain-terminal sessions in the unmanaged list stay Claude-only.
- **Chats**: every session as a conversation, on the phone and the web. The Chats list puts what needs you first (Needs you, Problem, To review), then the latest, with world chips and the real request on each row ("Run: npm test"). A chat shows the transcript as messages, with each run of tool calls folded into "N steps", the session's card above a message box, and a line for what you did on it ("You allowed once: …"). **Next / Skip** works through what needs you, and answering in that run opens the next one. On a phone the tabs are Chats / Rooms / Terminal and a chat takes the whole screen (Back returns to the list); on a wide screen **World / Chats** and **Conversation / Terminal** switch the panels. Claude only for now; other agents open in their terminal. Markdown is rendered with raw HTML and images off.
- The conversation (Scroll back, chats, catch-ups, handoffs) now includes the slash commands you sent, such as `/commit`; they were dropped as markup.
- **Antigravity CLI: Allow/Deny from Needs you.** agy sessions now run with `--dangerously-skip-permissions`, and every tool agy would ask about is held at its PreToolUse hook (timeout raised to an hour) until you allow or deny it, as Gemini's are; reads, searches and subagent bookkeeping run freely. When Agent Worlds can't be reached, `aw-hook` denies every agy tool, reads included. Where the project or a folder above it has its own `.agents/hooks.json` (which can switch our hook off by name), agy's own prompt stays the gate. Checked on agy 1.4.2.

## 2026-10-19
- **Antigravity CLI** (`agy`) as an agent, free with a Google account. Its sessions report tool use, and the end of a turn moves them to the Help desk; its permission prompts are answered in its terminal, since agy prompts whatever its hook answers. Its hooks live in `<home>/agy-hooks/.agents/hooks.json`, added to its workspace with `--add-dir`, and a note at session start names the project (agy otherwise works in whichever workspace folder sorts first). agy runs each subagent as a conversation of its own in the same terminal; they show as helpers of the session that started them. No mailbox: agy only reads MCP servers from `~/.gemini/config`. Works with agy 1.4.
- **Qwen Code on a server of your own**: the Model provider list can add any OpenAI-compatible server by name and address (key and model optional; the model is asked from the server's `/models` when left empty). Saved in `<home>/servers.json` (0600) and removable (`POST /api/providers`, `DELETE /api/providers/:id`). **Make default** next to Model provider makes New session start on it (`defaultProvider` in config.json, `POST /api/providers/default`).
- **Gemini CLI** as an agent, usable with a free AI Studio API key. Gemini can't let a hook answer its own tool prompt, so its sessions run with `--approval-mode yolo` and every edit, shell command or web fetch is held under Needs you until you allow or deny it (denied if Agent Worlds can't be reached or nobody answers). In a folder Gemini doesn't trust yet, or a repo with its own `.gemini/settings.json`, Gemini's own prompt stays the gate. The end of a turn moves it to the Help desk. Its sessions get a home of their own (`<home>/gemini-home`, linked to your `~/.gemini`) holding your settings plus the hooks and the mailbox; `~/.gemini` is untouched. Works with Gemini CLI 0.29 and 0.64.
- **Qwen Code with a model provider**: New session can run a Qwen session on OpenRouter, the Gemini API or Anthropic with a key and model of your choice, without touching `~/.qwen`. Keys are stored in `<home>/keys.json` (0600) and never sent back to a page (`GET /api/providers`, `PUT /api/providers/:id/key`, `provider` and `model` on `POST /api/sessions`).

## 2026-10-18
- Runs: a **New run** button at the top opens New session with steps already on. When Review code's `code-review.md` starts with CHANGES, the run goes back to the Build step before it (a new Build session gets the round and the review), up to 2 rounds; after that it waits for you. Review code no longer changes code itself. Each step's character and room chip show "step 2/4 · Review plan". Stopping a run and ending its sessions ends the earlier rounds' sessions too.
- Messages between sessions that have not been read are kept in `<home>/mailbox.json` and delivered after a server restart, once the recipient is back (for up to a day).
- A restart or update no longer counts as every session ending. Before, shutting down emptied `mailboxed.json`, so sessions lost their mailbox tools after an update, and left each running step of a run waiting as if its session had ended.
- Terminal: **End session** quits the session's agent and closes its tmux pane (only that pane, so a tmux session of yours keeps its other windows); the card goes. It always asks once, and says so when it would cut a turn short or drop a question. **Rename** gives a session a name shown on its name tag, the header, its room chip, the inbox and its panel; blank goes back to the repo name. Names are kept in `<home>/labels.json`, so they survive a server restart and follow `/clear` (`POST /api/sessions/:id/end`, `/api/sessions/:id/label`).
- Runs: **Stop and end its sessions** stops the run and ends every session its steps started; a stopped or finished run offers **End its sessions** while any are still open (`POST /api/runs/:id/stop` with `endSessions`).
- Recent sessions lists Kimi Code sessions too (marked Kimi, with your last prompt; archived ones left out), and **Resume here** brings one back with `kimi --session <id>` in its folder, reporting to Agent Worlds like any session it starts (`POST /api/sessions/resume` takes `agent: "kimi"`). "Continue in" from a Kimi session now finds its wire log: Kimi's hooks name the session `session_<uuid>`, and the lookup used to add a second `session_`.
- Esc in a Claude session puts it back at the lounge or help desk again. Claude writes "[Request interrupted by user]" on Esc, but other lines (system, last-prompt, file-history-snapshot, a helper's task notification) usually follow it, and the check only looked at the last line; a hook arriving after the Esc also made the marker look stale. It now takes the marker when it comes after Claude's last reply and after your prompt.
- Runs: New session can carry one task through steps on different agents (Plan → Review plan → Build → Review code by default, editable), each a session in the same folder. A step ends when its agent calls the new `aw_handoff` MCP tool; Agent Worlds writes a handoff and starts the next step. A step marked Check, or one whose turn ends without a handoff, holds the run under Needs you (Start next / Stop run). A step's panel shows the whole run. Step files go in `.aw/run-<id>/`, added to `.git/info/exclude`. Runs survive a server restart (`<home>/runs.json`) (`POST /api/runs`, `/api/runs/:id/next`, `/api/runs/:id/stop`).
- Text sent to a session (the reply box, the mail notice) now presses Enter a moment after typing it. Codex took an Enter right behind the text as part of a paste and left the message sitting in its input box.
- Sessions message each other, across agents: every session Agent Worlds starts gets the MCP tools `aw_agents`, `aw_send` and `aw_inbox` (through `bin/aw-mcp`, a stdio bridge to `/mcp` that names the pane it runs in). When a session that has mail is free, a one-line notice is typed into its terminal telling it to call `aw_inbox`; a session mid-turn is told when its turn ends. Messages show in both sessions' recent steps. Two sessions get 12 messages without a prompt from you, then are told to ask you.
- A Codex turn that ends without a hook no longer leaves the session at its desk: while it works, the server reads Codex's rollout log. A usage limit (`task_complete` carrying an error) shows an error card with Codex's message, Esc (`turn_aborted`) puts it back at its prompt, and a finished turn whose Stop never came shows as done.

## 2026-10-15
- "Continue in ▾" (a session's panel, or next to Dismiss on an error card) starts another installed agent in the same folder and branch, so the file changes carry over. It first writes a handoff to `<home>/handoffs/<session id>.md` — task, recent steps, working-tree state, plus Claude's conversation excerpt or a pointer to the other agent's transcript — and the new agent's first message is to read it and carry on. The old session stays untouched (`POST /api/sessions/:id/continue`).
- New sessions can run Kimi Code (`kimi`, 2.1+). It reports through the same hook, from a Kimi home of its own (`<home>/kimi-home`: links to `~/.kimi-code` plus a copy of its config.toml with the hooks), so your Kimi config is never edited. A starting task reaches Kimi as a one-shot `kimi -p` run that `kimi -c` then continues interactively (its TUI drops keys typed before it draws). Kimi doesn't wait on its permission hook, so its cards are answered in the terminal. Esc in Kimi (`Interrupt`) puts the session back at its prompt.

## 2026-10-14
- New sessions can run Codex or Qwen Code instead of Claude Code: an Agent choice in New session, with "Make default" (`defaultAgent` in config.json, Claude when unset or not installed). They report through the same hook (`aw-hook <agent>`), so rooms, the inbox and Allow/Deny work; always-allow rules, permission modes, catch-ups, resume and the terminal Restart stay Claude-only. `GET /api/agents`, `POST /api/agents/default`.
- Terminal: **Restart** quits the session's Claude and resumes the same conversation in a fresh one, in the same tmux pane, which redraws a wrecked screen for good. It keeps the session's permission mode, settings and model, and asks first when Claude is mid-turn (`POST /api/sessions/:id/restart`).
- Terminal text gets wrecked less: the terminal refits once its font has loaded, never squeezes the session to 0 columns while hidden, and starts clean after a reconnect.
- A session whose turn ends with only long-running background tasks (a dev server, an artifact watcher) goes to the Help desk instead of sitting at its desk with a clock: only background work started since your last prompt (a background helper or command, a monitor) means Claude is coming back. This also holds across a server restart.
- Room text stays readable on a phone: name tags and desk labels never shrink below about 10 px. Each chip under a room shows the branch. The overlap `!` sits left of the head, clear of the bubble and timer. README describes the illustrated rooms.
- A helper backgrounded mid-run (Ctrl+B) no longer sends its session to the lounge: it counts as running until it finishes, and neither Claude's idle notice nor the Esc check ends the turn meanwhile.
